# ISSUES — bugs, limitations, and open risks

> **What belongs here:** defects, known limitations, and risks that cut **across** phases — anything
> that could bite during operation or testing. One row per issue, newest first within each table.
>
> **What does NOT belong here:** build progress. `PROGRESS.md` is the phase board and the append-only
> handoff log; it stays the single source of truth for *what has been built*. This file is the single
> source of truth for *what is wrong or unfinished*. When they overlap, link — never restate.
>
> **How to use it:** every issue gets an id (`WC-nn`, never reused). When you fix one, move its row to
> **§2 Resolved** with the commit sha; do not delete it. The **"Affects testing?"** column exists so
> the owner can tell at a glance whether an open issue should change how they run a session.
>
> **Status:** `OPEN` · `INVESTIGATING` · `PLANNED` (a plan doc exists) · `OWNER-ACTION` (not a code
> fix) · `ACCEPTED` (known trade-off, no fix intended) · `RESOLVED`.
>
> Last updated: 05 Aug 2026 (WC-18/WC-19 / WC-R13/WC-R14).

| **WC-R11** | High | `3a82c68` | **WC-R10's close-detection never fired in practice** (was WC-16), because the model's own `"close"` action is structurally unreachable outside one narrow path: `Runner.respond()` only calls `advance()` (which can emit `"close"`) from inside the `action === "probe"` branch, once that thread's probe budget is exhausted — so a thread that completes via `"opener"`/`"acknowledge"` (the common case: the model says `thread_complete: true` without ever probing) falls through untouched, and nothing re-checks whether that was the *last* thread. On a cold-start session (empty brain, `open_threads: []`) there is no thread list to exhaust at all — the model free-narrates indefinitely and is never told `closing: true`, so per its own prompt rule (*"use only when told the session is ending"*) it structurally never says `close`. The owner's post-deploy retest was very likely a cold-start session, which is exactly the case WC-R10's fix could never reach. Fixed at the runner level, not just the UI: `respond()` now checks directly — once every brief thread is covered on a **non**-cold-start session, it forces `effectiveAction = "close"` and swaps in `THREADS_DONE_UTTERANCE` regardless of what the model chose that turn (guarded by a one-shot `announcedDone` flag so it doesn't repeat on every later turn). Cold-start sessions still can't be force-closed this way (there's nothing to exhaust), so the UI now also carries a permanent, always-visible caption under the *End & save* button (`.wc-savehint`) that doesn't depend on any close-detection at all — the one guarantee that survives every session shape. *Lesson: a "the model signaled it's done" guard is only as strong as the paths that can actually set that signal — trace EVERY branch that could complete the last unit of work, not just the one the original bug happened to go through, and always keep one detection-independent fallback for the case the signal can't exist yet (cold start).* |
